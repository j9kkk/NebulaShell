# E 融合：把参考界面的「三栏渐进披露」接进 Nebula Flow

> 前置：`12-d-direction-motion.md`（A 方向：浮岛分层 + 四档动效语言）。
> 本批不推翻 A，而是**替换它的信息架构层**：A 解决「观感与运动」，E 解决「操作动线」。
> 原型：`proto/A2-nebula-fusion.html`。状态：**待拍板**。

## 1. 参考界面到底是什么（客观拆解）

参考图是一个多智能体协作 IM（AI 助手拟人化成联系人，派任务、看执行、排错）。它的骨架实测：

| 层 | 宽度 | 承担职责 | 关键细节 |
|---|---|---|---|
| 全局图标轨 | 48px | 模块级切换 | 九个入口常驻，当前项浅蓝底；底部锚定头像/设置 |
| 对象选择栏 | 355px（26%） | 「找谁干活」 | 自带头部（模块名 + 在线状态 + ＋ + 折叠）、搜索、四个视图筛选、**两组分组列表** |
| 主工作面 | 520px（38%） | 「干了什么」 | 自带头部（对象 + 角色说明 + 事项数 + 动作图标）、**混合流**：普通气泡 + 任务卡片 + 系统变更日志、底部输入框 |
| 上下文抽屉 | 440px（32%） | 「这次具体怎么执行的」 | 自带两行头部（返回/类型徽章/标题/状态徽章/弹出/关闭 + 面包屑）、长 prompt 折叠、**结构化的错误诊断卡**、底部输入框内嵌运行时选择器 |
| 顶栏 | 28px | 只放窗口控制 | **没有任何菜单** |
| 底栏 | 无贯穿底栏 | 就近分布 | 每栏自己底部放东西 |

### 它符合直觉的 5 条机制（这才是要抄的东西）

1. **左→右渐进披露**：模块 → 对象 → 事件 → 细节，视线方向 = 操作方向。
2. **执行噪音右移**：上万字 prompt、HTTP 报错栈不进主对话流，只在中栏留一张**紧凑任务卡片**，点开进右栏。主流程永远可读。
3. **每栏自带头部 + 就近控制**：栏内动作在栏头，不在全局菜单；右栏输入框里直接内嵌「运行时 + 额度范围」选择器 —— 不用跑去设置页。
4. **事件卡片承载状态机**：`✓ 已完成` / `● 没做完` 是卡片上的语义色徽章，不是一个全局 toast。
5. **故障卡双层**：上层一句人话 + 一个蓝色主按钮（一键换运行时继续），下层折叠放 `HTTP 429 / 代理端口 / Trace ID / 复制诊断`。

### 融合后的骨架（1280×820）

```
┌──────────────────────────────────────────────────────────────┐
│ 28px 顶栏：✦ NebulaShell · 工作区「内容运营」   [窗口控制]      │  ← 无菜单
├────┬───────────────┬────────────────────────────┬────────────┤
│48px│ 对象栏 300px   │ 主工作面 40%                │ 抽屉 32%    │
│轨  │ ┌ 主机 12 ＋⋯ │ ┌ 头部：api-prod-01 已连接12ms│ ┌ 头部      │
│    │ │ 搜索         │ │                            │ │ 面包屑    │
│ ●  │ │ 生产 8       │ │  终端（xterm，保持平）      │ │ 事件卡片  │
│ ○  │ │  api-prod-01 │ │                            │ │ 诊断卡    │
│ ○  │ │  cache-…     │ │                            │ │ 输入框+模型│
│ ●  │ │ 预发 4       │ │                            │ └────────────┘
│    │ └ 已收藏 2     │ └ 事件条：3 条               │
└────┴───────────────┴────────────────────────────┴────────────┘
```

三处关键取舍：

- **取消 45px 全局状态栏**：连接状态进主工作面头部（`已连接 · 12ms`），传输进度进左轨底部胶囊 + 右栏；窗口最底只留 2px 活动脉搏（借用 B 方向）。
- **右栏默认常驻**（32%），但**980px 最小宽度下自动收成 44px 图标条**，点击浮出覆盖主区（否则终端只剩 380px，不可用）。
- **终端区依然是唯一「平」的区域**：不加圆角裁剪、不加滤镜、不叠半透明层。事件条在主区**头部之下**、终端**之上**的一条 28px 折叠带，不遮终端。

## 5. 验收口径

- 1280×820 / 980×640 两档：无横向滚动、无文字截断、终端可视宽度 ≥ 420px（980 档右栏收起后）。
- 三栏各自独立滚动，栏头吸顶，事件条不遮终端首行（首行净空 ≥ 6px）。
- 动效关掉后布局成立；`prefers-reduced-motion` 只保留 opacity。
- 诊断卡必须同时给：一句人话结论、主恢复按钮、折叠的技术细节（退出码 / stderr 首行 / Trace ID）。

### 本轮修掉的缺陷（视觉复核提出，逐条复测）

1. 首屏未切场景 → 右栏 AI/传输/诊断三类卡片同时显示、状态自相矛盾（`setScene('terminal')` 补在初始化）。
2. 分屏面板长命令被硬裁切 → `white-space:pre-wrap; overflow-wrap:anywhere`。
3. 主机行 40px 时第三行 meta 占位把文字顶到上沿 → meta 改 `max-height:0` 折叠，实测 7/20 垂直居中。
4. 计数与可见行数不符（12/8/4 vs 6 行）、`web-staging-03` 误放在生产组 → 计数改为 6/2/3，分组归位。
5. 灰点离线主机却显示延迟 → 离线一律 `—`；「常用 2」补星标。
6. 会话栏加胶囊后主机名/地址折行 → `flex:none + nowrap`，胶囊只留 1 个 + `+`，分隔线区分操作组。
7. 空态主区仍显示在线终端 → 新增 `.work-empty`，empty 场景整块替换。
8. `prefers-reduced-motion` 缺失 → 补齐。
