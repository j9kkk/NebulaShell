# D 方向：从「方框拼接的终端」到「有重力的工作台」

> 状态：**待拍板**。前置：B0–B6 样式债清零、C1 换皮（深空冷调·克制）、C2 门禁归零。
> 本文只定方向与规格，不动仓库代码。两份动效原型见 `proto/A-nebula-flow.html`、`proto/B-command-deck.html`。

## 0. 结论先行

现在这套界面**不缺颜色，缺运动**。C1 已经解决了「层级分不开、对比度不够」的问题，
但 144 处 1px 描边把所有分区画成了一张表格，而 55 处 transition 里只有 6 处动 `transform`、
11 处只动 `opacity` —— 也就是说，**绝大部分交互反馈是「换个颜色」，不是「有东西在动」**。
所以「灵动」不是再加几个 hover 效果，而是三件事：

1. 把「描边分区」换成「浮岛分层」（结构，决定观感现代与否）；
2. 把「一条曲线三档时长」换成「四档时长两条曲线 + 一条只用于出现」（动效，决定灵动与否）；
3. 把「每处交互都平铺在屏幕上」换成「信息随交互展开」（密度，决定高效与否）。

## 1. 诊断：实测数字

| 维度 | 实测 | 判断 |
|---|---|---|
| 1px 描边声明 | **144** 处 `border: 1px solid`，145 处引用 `--border` | 分区全靠描边，视觉上等于表格；没有「浮起」层级 |
| 阴影 | 四档 token（xs/sm/pop/panel）但只用于浮层 | 常驻面板一律贴边平铺，没有重力 |
| `backdrop-filter` | 全站 **1** 处 | 唯一「材质」语言：没有虚化/景深线索 |
| transition | **55** 处 | 数量够 |
| 其中动 `transform` | **6** 处 | **几乎没有位移**，切换看不出方向 |
| 其中只动 `opacity` | **11** 处 | 纯淡入淡出读不出「从哪来、到哪去」 |
| 时长档 | 0.12 / 0.15 / 0.18s（另有 3 处硬编码 `0.3s ease`） | 差 60ms，肉眼归为同一档；没有「按压更快、面板更慢」的节奏 |
| 缓动曲线 | 3 条，主用 `cubic-bezier(.2,0,.2,1)`（近似匀速） | 没有进入/退出分离，没有物理感 |
| keyframes | 14 个，多数是 `pulse`/`spin` 循环动画 | 只服务「状态」，不服务「切换」 |
| 圆角 | 4 / 8 / 10 / 12 / 999 六档 | 档位健康，可整体上提一档（8→10 主体） |
| 最小窗口 | 980×640（`tauri.conf.json`） | 原型与断点必须按 980 宽验 |
| 主机行 | 44px 单行两段文本 | 密度中庸：hover 不揭示任何新信息 |

一句话：**现在的动效是「颜色开关」，不是「运动」。**

另外两条属于结构债、不是 token 能修的：

- **欢迎页 3/4 屏是空的**。居中一个 logo + 三个按钮，是最典型的「没想好第一屏该放什么」。
  对天天用的工具类产品，首屏价值应该来自「最近连的 3 台 + 常跑的 6 条命令」，而不是品牌标语。
- **活动标签/选中行各自带状态**（每行自己一个 `::before` 指示条、每个标签自己一份背景），
  切换时是「旧的灭、新的亮」两次突变，而不是「一个指示器滑过去」一次运动。

## 2. 三条设计原则（以及明确不做的）

### P1 浮岛分层：用表面台阶定边界，只在必须时用发丝线

- 常驻区从「通栏描边」改为「带 8px 缝隙的岛」：左岛（主机）、中岛（终端/工作台）、右岛（工具抽屉）。
  岛与岛之间露出更深一档的画布底，边界靠 **L\* 台阶 ≥4** 而不是 1px 灰线。
- 终端区是唯一允许「平」的地方：xterm 的 canvas 不能被圆角裁剪、不能叠滤镜做虚化——
  它对 `filter`/`backdrop-filter` 的代价最敏感（WebKitGTK 会退到非 GPU 路径）。
  所以「让背景变暗」用**叠加一层 `rgba(0,0,0,.14)` 的遮罩**，不用 `filter`。
- 1px 线只保留三类：表格行分隔（信息密集处必须）、输入框内缘、弹出层的 1px 发丝高光。

### P2 一套动效语言：四档时长、两条曲线、一条「只用于出现」的弹簧

现有 `.12/.15/.18 + 一条匀速` 的问题不是数值不对，而是**所有东西同速同曲线**，看不出主次。
新体系（全部进 token 层，组件不允许写字面时长）：

| token | 值 | 用在哪 |
|---|---|---|
| `--dur-1` | 80ms | 按压（scale .97→1）、图标微转、焦点环展开 |
| `--dur-2` | 140ms | 颜色、描边、图标填充、hover 离开 |
| `--dur-3` | 220ms | 位移：指示器滑动、展开收起、抽屉进出 |
| `--dur-4` | 320ms | 整块内容切换（磁贴重排、页面级淡入） |
| `--ease-out-expo` | `cubic-bezier(.16,1,.3,1)` | **进入**：位移、展开、面板出现 |
| `--ease-in-out` | `cubic-bezier(.65,0,.35,1)` | **退出**：收起、消失 |
| `--ease-spring` | `cubic-bezier(.34,1.56,.64,1)` | **只用于「出现」**，永不用于退出 |

三条硬规则：

1. **进入快、退出慢（且不同曲线）**：hover 进入 `--dur-1`，离开 `--dur-2` 并换 `--ease-in-out`。
   退出用同一条曲线是「闪烁感」的来源。
2. **可感知的切换必须有方向**：用「位移 + 形变 + 透明度」三者之二，禁止纯 opacity 淡入淡出
   （方向读不出来，用户只会觉得「卡了一下」）。
3. **只动 `transform` / `opacity` / `filter`**，不动 `width/height/left/top`。
   现有 3 处 `transition: width .3s`（`.fp-task-bar > i`、`.mono-bar` 等）在进度场景要换成 `scaleX`。

### P3 信息随交互展开：把「高效」做在 hover 里，不做在设置里

- 主机行 44px 单行 → 40px 常态、**hover 长到 56px 揭示第二行**（最后连接 / 负载 / 延迟）。
  静止时更紧凑，鼠标停上去才给细节 —— 密度和效率同时拿。
- 低频动作继续收进右键/`⋯`（用户已有明确偏好），**不加常驻按钮**。
- 首屏从「居中三按钮」改为**发射台**：最近连接 3 卡 + 快捷命令 6 胶囊 + 云主机发现横幅。

## 3. 两个方向，一个推荐

| | **A 浮岛 · Nebula Flow（推荐）** | **B 编排 · Command Deck（对照组）** |
|---|---|---|
| 结构 | 保留「侧栏 + 标签 + 主区」三段式，改为浮岛与阴影分层 | 取消标签行，改命令条 + 统一流（主机/会话/传输混排）+ mosaic 磁贴 |
| 大胆在哪 | 空间与材质：去描边、加台阶、抽屉浮起 | 信息架构：会话从「标签」变成「磁贴」，可 1/2/4 格重排 |
| 动效重心 | 方向性运动：指示器 FLIP、抽屉滑入、stagger | 编排：磁贴 FLIP 重排、键盘焦点环、更快更硬（90/140/200ms） |
| 改动面 | 中：CSS 为主 + 少量 DOM（浮岛容器、指示器元素） | 大：标签行→命令条、窗格→磁贴，触及 `terminal-layout.js` 与 `split-layout-renderer.js` |
| 风险 | 低：信息架构不动，回滚只需换回 token | 高：mosaic 与现有 PTY resize 策略要重新对齐（`terminal-layout.test.mjs` 会全红） |
| 适用 | **推荐先做**：一次拿到「现代 + 灵动」的主收益 | 只取其中「统一流」与「活动脉搏」两条，作为 A 的 D3 可选批次 |

**推荐 A**，理由三条：

1. 「灵动」的收益 80% 来自 A 的三个动作（指示器滑动、抽屉方向性进出、hover 展开），
   而它们都不动信息架构 —— 也就是说 A 有 B 的大部分观感收益，却没有 B 的 resize 风险。
2. B 的磁贴重排很漂亮，但它跟现有「按窗口尺寸自动布局 + 拖拽调宽 + 同步远端 PTY」的契约
   （`docs/ui-layout-contract.md`、`terminal-layout.js`）冲突，等于重写布局层；
   在一次「换观感」的迭代里不值得。
3. B 的「底部只留 2px 活动脉搏」这条**单点收益很高**（去掉 45px 常驻状态栏的沉重感），
   单独摘出来放进 A 的 D3 批次即可，不必为了它接受整个 mosaic。

## 4. 每处交互的动效规格（可交付开发）

`A` 方向要实现的清单。每行都能直接对应一个选择器 + 一条 transition/animation。

| # | 交互 | 触发 | 属性 | 时长 / 曲线 | 对应代码 |
|---|---|---|---|---|---|
| 1 | 主机行 hover | `:hover` | `height 40→56`、meta 行 `opacity 0→1` + `translateY(3px→0)` | 220ms / out-expo | `.host-item`（现 `:hover` 只换背景） |
| 2 | 行选中指示器滑动 | 点另一行 | 独立元素 `translateY`（FLIP 量测后设置） | 220ms / out-expo | 新增 `.host-indicator`，替代 `.host-item.active::before` |
| 3 | 主机行按压 | `:active` | `scale .985` | 80ms / standard | `.host-item:active` |
| 4 | 标签 pill 滑动 | 切标签 | 独立元素 `translateX + width`（FLIP） | 220ms / out-expo | 新增 `.tab-pill`，替代 `.tab.active` 背景 |
| 5 | 新标签出现 | 新建 | `scale(.92)→1` + `opacity 0→1` | 220ms / spring | `.tab` 进入 |
| 6 | 标签关闭 | 关闭 | `width→0` + `opacity→0`（相邻标签让位） | 160ms / in-out | `.tab.closing` |
| 7 | 右侧工具抽屉 | `⌥⌘B` | `translateX(16px)→0` + `opacity`；内部区块 stagger 25ms | 320ms / out-expo | `.ai-panel` / `#right-panel` |
| 8 | 抽屉陪伴效果 | 同上 | 终端区叠加遮罩 `rgba(0,0,0,0)→.14`（**不用 filter**） | 320ms / in-out | `#term-stack::after` |
| 9 | 命令面板出现 | `⌘⇧P` | 面板 `scale .96→1` + `translateY 8→0`；列表 stagger 18ms；背板 `backdrop-filter: blur(8px)` 从 0 到 8px | 320ms / out-expo | `.palette`（全站唯一 blur 场景） |
| 10 | 欢迎卡 hover | `:hover` | `translateY(-2px)` + 内流光 `background-position` 扫过 | 220ms 抬起 / 600ms 流光 | `.launch-card` |
| 11 | 快捷命令胶囊 | `:hover` | 图标 `rotate(8deg) scale(1.06)` | 140ms / out-expo | `.cmd-chip` |
| 12 | 连接状态点 | 状态变化 | `connecting` 呼吸 1.1s；`connected` 静亮 | 循环 animation | `.host-dot`（沿用） |
| 13 | 传输进度 | 传输中 | 进度条 `scaleX` + 1.2s 流动光泽 | 循环 | `.fp-task-bar`（改掉 `width` 过渡） |
| 14 | 分屏焦点环 | 点窗格 | 聚焦窗格 `box-shadow` 环展开；非聚焦窗格遮罩加深 | 200ms / out-expo | `.term-pane.focused` |
| 15 | 侧栏收起/展开 | `⌘B` | 宽度过渡沿用，但换 `--dur-3 / out-expo` | 220ms | `#sidebar`（现 `--dur/--ease`） |
| 16 | 全局 `prefers-reduced-motion` | 系统设置 | 位移/缩放归零，只保留 opacity | — | `@media (prefers-reduced-motion: reduce)` |

> 硬约束：以上全部走 token；组件里不出现 `0.3s`、`ease`、`cubic-bezier(...)` 字面值。
> 现在的 3 处硬编码 `0.3s ease`（第 2044 / 2094 / 3291 / 3639 行附近）在 D0 一并清掉。

## 5. 分期：四批，每批独立验收

| 批次 | 内容 | 预期观感变化 | 验收 |
|---|---|---|---|
| **D0** | 动效 token 层（7 个新 token）+ 清 4 处硬编码时长 + `prefers-reduced-motion` 兜底 | 画面零变化 | `ab` 净差 0；`lint:css` 0/0/0 |
| **D1** | 浮岛分层：去通栏描边、加 8px 缝隙、圆角主体 8→10、标题栏改顶部高光 | **第一批可见改版** | 暗/亮 × 4 场景截图；L\* 台阶脚本复跑（≥4） |
| **D2** | 运动语言：指示器 FLIP（#2/#4）、抽屉方向性进出（#7/#8）、命令面板（#9）、hover 展开（#1/#10/#11） | 交互手感变化 | 每项录 15s 实机 + 中途帧截图（不得出现半帧） |
| **D3** | 状态与效率：焦点环（#14）、进度 `scaleX`（#13）、发射台首屏、**可选**：状态栏压缩为 2px 活动脉搏（B 方向摘件） | 首屏价值 + 状态可读 | 定点截图 + 键盘路径走查 |

每批不跑全量 e2e（铁律）：`build:web` → `up --build` → `scene` → `shot` / `ab` → `token-contrast`。

## 6. 风险与不做的事

- **不做毛玻璃常驻面板**：`backdrop-filter` 在 WebKitGTK 上会把整块拉到独立合成层，
  常驻使用等于每帧多一次全屏采样。全站只允许命令面板这一处。
- **不碰 xterm 的绘制路径**：终端区不加 `filter`、不含圆角裁剪（会切掉字形边缘）、不叠半透明层
  （透明度叠加会让文字对比度掉档，且 WebGL 渲染器的 clear color 是写死的）。
- **不新增圆角/字号档位**：主体 8→10 是唯一允许的档位迁移。
- **不改键盘契约**：所有快捷键表（README 那张）不动。
- **亮色同步**：每批都要出暗/亮两套截图，浮岛在亮色下更容易糊成一片（`--bg` 与 `--panel` L\* 台阶要重算）。
