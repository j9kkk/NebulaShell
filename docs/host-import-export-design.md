## 0. 一句话结论

审计暴露的不是"弹窗不好看"，而是三类结构性问题：

1. **说了假话**：导出文件恒含全部凭据，卡片一字未提；「内置密钥」只是二进制里的固定 seed，却被写成"保护"（F-01/F-02，P0）。
2. **承诺了做不到的原子性**：预检与落盘各读一次文件（TOCTOU），落盘失败时内存已改、磁盘没改（F-04/F-05）。
3. **把决定权藏起来**：范围只能在入口决定、预览只给 8 行、不能只导入其中几台、错误没有行号、覆盖范围大于 diff 展示（U-01/U-05/F-07/F-08/F-09）。

本方案用 **一张卡三步**（选择 → 预览/逐行勾选/冲突 → 结果）取代两层弹窗，用 **一份字段注册表** 对齐模板与导出，
并把"文件里到底有什么（凭据、跳板、覆盖哪些字段）"变成卡片上必须先看到的事实，而不是事后 toast。

### 1.1 与「表格通道（CSV/XLSX）」的关系

卡片要求设计"模板 / 字段映射 / CSV、XLSX"，审计 §5 明确"新增导入格式是产品决策，不是缺陷修补，本期不建议做"。
两者不冲突，但**不能混在一批里**：

- **P0**（本期，审计 31 条）：只动现有 JSON 通道的交互与后端一致性。
- **P1**（表格通道）：§8 给出完整、可实现的契约（字段注册表、模板、CSV 导入/导出、XLSX 导出），
  但**默认不进入本期实施**，需要产品裁决后单独开卡（审计 §5 的结论）。

本文所有 P0 结论都不依赖 P1。P1 上线前，卡片上**不显示**模板下载链接（避免死入口）。

### 1.2 并行卡已落地、本文沿用的能力（不要回退）

| 已落地 | 位置 | 本文如何处理 |

## 2. 术语与对象模型

| 术语 | 含义 | 代码对应 |
|---|---|---|
| **备份包** | `.json`，`version:4`，hosts 全字段 + `credentials`（内置密钥或口令）。**唯一能携带凭据的格式。** | `export_hosts_scoped()` / `parse_export()` |
| **表格**（P1） | `.csv` / `.xlsx`，10 个非敏感字段；导出与模板同表头；导入只收 CSV。 | §8，新增 |
| **行** | 导入最小单位。CSV = 文件物理行（表头第 1 行）；JSON = `hosts[i]`，界面写「第 N 台」。 | `inspect.rows[].row` |
| **处置** | `written 新增 / overwritten 覆盖 / filled 补凭据 / skipped 跳过 / unchanged 未改动`。与现有 `RESULT_LABEL` 一致，**不新增第六种**。 | `transfer.js` `RESULT_LABEL` / `tallyResult` |
| **排除** | 用户在预览里取消勾选的行：不发往写入，结果里计 `skipped`，原因 `未选中`。 | `decisions[key]='skip'` |
| **附带** | `ids` 范围导出时后端自动补进来的跳板机（含其凭据）。 | `includedJumps` |
| **报告** | 结果态导出的 CSV：位置、主机、地址、字段、处置、原因。 | 新增 `hosts:importReport` |

**计数恒等式**：`written + overwritten + filled + skipped + unchanged = 文件内主机数`；
其中 `skipped` 再分两种原因：`用户排除` / `冲突跳过`（同一桶，报告里写原因）。

### 3.2 导入链路（审计快照）

`选文件 → hosts:importInspect（读一次）→ 8 行预览 → [冲突卡] → hosts:importApply（**再读一次**）→ 备份 → 内存替换 → save()`。
关键事实：预检与落盘两次读盘无一致性校验（F-04）；`data["hosts"] = staged; self.save()?` 的顺序使失败时内存已改（F-05）；
解析错误是整批一句话（F-09）；一行坏即整批不可导入（F-08 的反面）。

### 3.3 导出链路

`入口决定 scope → 卡片（范围/分组只读、路径、私钥、加密）→ hosts:exportFile（同步写盘）→ 关窗 + toast`。
关键事实：`creds` 无条件收集全部凭据（F-01）；`CRED_ALG_V4` 的密钥来自二进制固定 seed（F-02）；
`ids` 模式自动补跳板机并带其凭据，前端从不展示 `includedJumps`（F-06）；文件 `0644`（F-12）；
路径拆分成 `dir`/`filename` 的规则会把目录当成文件名（F-11）；扩展名不校验（F-10）。

## 5. 入口设计

### 5.1 命名（唯一来源）

| 命令 | 注册表 label | 菜单面 | 其它表面 |
|---|---|---|---|
| `host.new` | `新建主机` | `新建主机…` | `新建主机` |
| `hosts.import` | `导入主机` | `导入主机…` | `导入主机` |
| `cloud.import` | `从云导入` | `从云导入…` | `从云导入` |
| `hosts.export` | `导出主机` | `导出主机…` | `导出主机` |

- 四个 label **已是现状**，不改注册表，只把各处手写文案收敛到它们（卡片要求：统一为「导入主机 / 导出主机」）。

- **不合并**成一个「添加主机」三选一向导：云导入带账号/区域/分页状态，塞进通用向导弹窗会让状态机翻倍；来源词已经把"东西从哪来"说清（§13）。

| 表面 | 改后 | 动作 |

### 6.7 实现细节问答（写代码前不再问）

| 问题 | 结论 |
|---|---|
| 步骤 2 返回步骤 1 后，已选文件还在吗？ | 在。路径、口令、解析结果保留；重新选择才清空。 |
| 问题行为什么不能勾选？ | 它们没有可信数据。修正文件后重新读取即可；不想修就只导有效行（默认就是）。 |
| 冲突行取消勾选与选"跳过"有区别吗？ | 结果相同（都计 `skipped`），区别只在报告原因：`未选中` vs `冲突跳过`。 |
| `im.decisions` 结构？ | `{ "<row key>": "skip" \| "overwrite" \| "new" }`，覆盖**所有行**（不止冲突）。 |
| 全局策略与逐台冲突怎么办？ | 全局策略写入全部冲突键；逐台改只改该键；再点全局会覆盖逐台。 |
| 预览排序？ | `invalid`（不可选）→ `conflict` → `credOnly` → `add` → `identical`，同组按文件顺序。 |
| 没冲突还要过步骤 2 吗？ | 要。步骤 2 是"确认写什么"的唯一位置。 |
| 导入成功后 toast？ | **没有**。结果态是唯一报数处（D8）。 |
| 结果态关闭后还能看报告吗？ | 明细可先「下载明细」；关闭后不保留。 |
| 从主机库进入，完成后主机库还开着吗？ | 开着并刷新；`完成` 只关导入卡。 |
| 明细报告默认文件名？ | `nebulashell-import-report-2026-11-03-0102.csv`（本地时间 `YYYY-MM-DD-HHmm`）。 |
| 报告对话框取消？ | 什么都不发生，结果态保留。 |
| 大文件/慢口令的进度条？ | 不确定态（不画百分比）；文案 `正在写入 12 台主机…（一次性写入，不可取消）`。 |

### 8.2 解码规则（P0 也要，F-03）

`decode_text(bytes)`，JSON 与 CSV 共用：

1. UTF-8 BOM（`EF BB BF`）→ 去 BOM，按 UTF-8。
2. UTF-16 BOM（`FF FE` / `FE FF`）→ 按 UTF-16 LE/BE 解码后转 UTF-8。
3. 无 BOM：偶数长度且奇/偶位零字节比例 >30% → 判 UTF-16。
4. 其余按 UTF-8；失败 → 尝试 GBK（`encoding_rs`）；再失败 → `E_ENCODING`。
5. 错误文案不能出现 `stream did not contain valid UTF-8` 这类原文。

CSV 额外规则：`,` 分隔、RFC4180 引号、表头第 1 行；未识别列忽略并提示 `已忽略 1 列：备注`；缺「地址」列 → 阻断。

### 8.3 字段映射（仅 CSV）

全部命中 → 只显示 `已识别 10 列`；有未命中 → 展开 10 行「字段 → 列名 / 不使用」；必填未映射 → 标红 + 主按钮禁用。
不提供"保存映射方案"（一次性导入）。

### 8.4 XLSX

导出：`rust_xlsxwriter`（纯 Rust）。单 sheet `主机`，首行加粗冻结，列宽自适应。
导入：**不支持**，选到 `.xlsx` 明确提示 `请先在 Excel 里「另存为 CSV」，再导入`，并写进步骤 1 的格式说明。

### 8.5 JSON 备份

字段固定（v4 全字段）；`credentials` 由内置密钥或口令加密；导入兼容 v1–v4，v5+ 报 `E_VERSION`。
P0 的改动只有：`withCredentials:false` 时省略 `credentials` 并置 `credentialsIncluded:false`（F-01 的"不含凭据"开关）。

### 9.3 报数（唯一来源）

- 五个桶：`written/overwritten/filled/skipped/unchanged`，由 `tallyResult(result.rows)` 计算；后端 `result` 里的汇总数字**不直接上屏**（避免 F-13 的两套口径）。

### 10.1 `hosts:exportFile`（扩展，向后兼容）


### 10.2 `hosts:importInspect`（扩展）

```jsonc
// 请求：{ "path": "…", "passphrase": "…" }（path 空 = 弹系统文件框）
// 响应 A：需要口令
{ "needsPassphrase": true, "path": "…", "file": { "name":"…", "size":12345, "format":"json" } }
// 响应 B：成功（有坏行时同样成功返回,靠 rejected/invalidRows 区分）
{
  "path": "…",
  "bytes": 12345,                           // 文件字节数(与 digest 同一份读入)
  "digest": "sha256:9f2c…",                 // 落盘校验用（F-04）
  "file": { "name":"a.json", "bytes":12345, "exportedAt":"…",
            "version":4, "encryption":"builtin", "count":12 },
  "inspect": {
    "counts": { "add":7, "credOnly":1, "conflict":1, "identical":0, "invalid":3 },
    "rows": [{
      "key": "…", "name":"…", "host":"…", "port":22, "username":"root",
      "group":"…", "kind":"add",                    // add|credOnly|conflict|identical|invalid
      "local": null, "diff": [], "hasCredentials": true,
      "errors": []                                  // kind=invalid 时带该行问题
    }],
    "rejected": true,                               // 有坏行但未全部收敛(F-09)
    "code": "E_INVALID_PRESENT",                    // rejected 时给出错误码
    "message": "导入文件校验失败（共 3 处问题）…",     // 人话摘要(问题区折叠用)
    "invalidRows": [{ "index":3, "line":9, "name":"坏行 db",
                      "field":"port", "code":"E_PORT", "reason":"端口必须…70000" }]
  }
}
// 响应 C：用户取消 → null
// 响应 D：文件级错误(编码/JSON/版本/口令/空文件/超上限) → 调用失败；message = 中文文案（含 code），禁止 io/serde 原文
```

- **逐行收集**，不在第一个坏行返回（F-09）。
- 单文件上限 5000 台（`E_ROW_LIMIT`）；**只读一次、只解析一次**（meta 从同一份 bytes 计算，F-16）。
- 编码走 §8.2 的 `decode_text`（F-03）。

### 10.3 `hosts:importApply`（扩展）

```jsonc
// 请求
{
  "path": "…", "passphrase": "…",
  "digest": "sha256:9f2c…",                  // 必填；缺失或不符 → E_FILE_CHANGED
  "decisions": { "<row key>": "skip" | "overwrite" },   // 覆盖所有行
  "allowPartial": false                      // 默认 false=整份拒绝；true 才跳过坏行
}
// 响应
{
  "result": {
    "added": 8, "overwritten": 1, "filled": 0, "skipped": 3, "unchanged": 0,
    "invalid": 1,                            // 被跳过的问题行数（allowPartial 时 >0）
    "updated": 1,                            // = filled，兼容既有断言
    "withCredentials": 10, "credentialsFilled": 0,
    "backup": "/…/backup/nebulashell-backup-20261103-0102.json",
    "rows": [{ "row":2, "key":"…", "name":"…", "result":"written", "reason":null }]
  }
}
```

**写入顺序（F-05，必须按此实现）**：

1. 读文件 + 校验 `digest`（不符 → `E_FILE_CHANGED`，不写）。
2. 在 `staged` 副本上应用决策（不碰内存里的 `data`）。
3. `validate_jump_graph(&staged)`。
4. 备份当前库（失败则中止，`E_WRITE`）。
5. 写临时文件 `hosts.json.tmp` → `rename` 覆盖正式文件（成功后内存才替换为 `staged`）。
6. 任何一步失败：内存保持导入前；返回 `E_WRITE` + 中文原因。

- 决策语义：`skip` 对任何行都有效（add 行被排除时计 `skipped/未选中`）；冲突行只有「跳过 / 覆盖」两种处置（`new` 未落地）。
- 私钥安装：`keys/<hostid>-<n>-<name>`，`0600`；失败写 `E_KEY_INSTALL`（F-15）。
- 结果 `rows[].result` 六值（与前端 `RESULT_LABEL` 一致）：`written / overwritten / filled / skipped / unchanged / invalid`；
  坏行在 `allowPartial: true` 时记 `result:"invalid"` + `reason:"端口必须在 1–65535 之间…"`。
- `digest` 是 `sha256:` + sha256 前 16 字节十六进制；**缺省视为不符**（否则省略指纹就能绕过 TOCTOU）。
- 预检（`hosts:importInspect`）在有坏行时**不返回错误**，而是 `rejected: true` + `code:"E_INVALID_PRESENT"`
  + `invalidRows`（结构见 §10.2），并照常给出有效行的 `rows`（坏行 `kind:"invalid"`，前端禁用勾选）。
